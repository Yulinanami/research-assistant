## 3.1.2 功能清单与功能说明

定位：让人员评价和修改已有数据，尤其适合问答、模型回答评分及偏好收集。问答内容通常由上游准备，Argilla 保存人工反馈。

| 序号 | 功能模块 | 功能说明 | 对应本项目功能 |
| --- | --- | --- | --- |
| 1 | 数据集导入 | 从 Hugging Face 或 Python SDK 导入，设置展示字段 | 待标注数据上传 |
| 2 | 评价项配置 | 配置评分、单选、多选、文本修改或排序 | 问答对标注、人工评价 |
| 3 | 标注操作 | 对照问题、答案和参考材料，评分、选择或填写修改 | 标注结果检查与修订 |
| 4 | 状态与筛选 | 区分待处理、草稿、已提交等状态，按条件查看 | 标注进度与任务筛选 |
| 5 | 反馈保存与导出 | 保存原始字段和人工反馈，通过 SDK/API 导出 | 标注成果交付 |

评分项和标签由任务配置决定，不存在统一适用于所有数据的评分标准；使用排序收集偏好还需要准备候选答案。

## 3.1.3 优势功能分析

### 优势功能1：原始内容与评价分别保存

- **功能描述：** 展示问题、回答和参考材料，分别填写评分及修改答案。
- **技术实现：** 字段保存原始内容，Response 保存标注者提交的反馈。
- **差异化价值：** 可以比较修改前后内容，避免原始回答被直接覆盖。
- **可借鉴方向：** 保留原文、评分和修订，按任务决定最终采用哪个结果。

### 优势功能2：评价项可按用途组合

- **功能描述：** 将质量分、可用性、修改文本或候选答案排序组合到同一任务。
- **技术实现：** Settings 定义展示字段和评价控件，界面按配置收集反馈。
- **差异化价值：** 可围绕具体质量问题收集结构化意见。
- **可借鉴方向：** 明确评价标准；缺少原文依据时允许选择无法判断。

### 实际体验

已通过 Docker Compose 启动本地服务，体验 Hugging Face Dolly 数据集导入与评价项配置，随后导入 Easy Dataset 问答，执行评分、可用性判断和答案修改。

2026-10-19 核对现存本地导出文件：包含 223 条记录，其中 2 条带人工反馈，原始字段与反馈分别保存。该结果证明数据可导入并导出，但不代表整批记录均已完成标注。

早期将含思维链的内容展示为回答，是源数据和字段映射需要检查的问题，不能归结为 Argilla 自动生成了思维链。辅助脚本现按原样导入，不强制执行清洗。

## 3.1.4 技术架构概述

- **整体架构：** 前端和 Python SDK 调用 FastAPI Server，数据库保存记录与反馈，搜索引擎提供索引。
- **核心依赖：** 本次 Compose 包含应用、worker、PostgreSQL、Elasticsearch 和 Redis。
- **模型支持：** 可接收外部模型生成的答案或建议，评价操作本身无需运行大模型。
- **扩展机制：** Python SDK、REST API、数据集配置及 Webhook。[C11]、[C36]

## 3.1.6 与本项目的关系

- **可直接集成的能力：** 优先验证问答评分、可用性判断、答案修改及反馈导出。
- **可借鉴的设计理念：** 原始记录和人工意见分开保存，草稿与提交明确区分。
- **本项目相对优势：** 规划包含文档解析、清洗、生成和成果发布，Argilla 主要负责人工反馈。
- **本项目相对短板：** 评价规则、审核职责、修改答案的采用方式仍需设计，不能只统计提交数量。

可接收 Easy Dataset 生成的问答；如需清洗，由 Data-Juicer 按任务规则处理。已有脚本仅用于文件导入导出，不属于 Argilla 自带的自动导出功能。

## 3.1.7 调研结论

| 评估项 | 结论 |
| --- | --- |
| 推荐集成/借鉴程度 | 高：问答人工评价；长期集成需安排维护 |
| 技术成熟度 | 本地导入、评分、修改与导出已体验；多人评价和排序待验证 |
| 社区活跃度 | 沿用基本信息中的原调研记录，持续维护需单独评估 |
| 一句话总结 | 适合检查和修订已有问答，结果交付需要明确导出范围与反馈采用方式 |

提交后自动保存到数据库，并不会自动生成可浏览的 JSON 导出目录。本次数据库在 Docker 数据卷中；本地文件由脚本另外导出。导出的修改答案仍在反馈中，不会自动替换原回答。上述保存方式与导出范围应在操作界面中说明，避免误解。[C12]、[C29]
