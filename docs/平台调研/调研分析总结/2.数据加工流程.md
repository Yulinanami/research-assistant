科研资料采集 → 文档解析 → 数据清洗 → 知识片段 → 问答生成与人工标注 → 质量审核 → 版本发布 → 科研知识库或模型应用。

当前 PDF 问答生产主流程采用：MinerU 解析 → Data-Juicer 按需清洗 → Easy Dataset 分块、生成问答并人工修改。Docling 作为其他格式或替代解析的候选，Label Studio、Argilla 按标注和评价任务选用。下面是建议的工具分工，尚未实际连接各工具验证。

## 2. 按需求阶段看六个平台如何参与

### 2.1 需求定义与数据规划

对应需求：全流程标准、数据字典、清洗流程、规范步骤索引；数据需求定义（数据集名称、使用场景说明、质量要求定义、数据来源说明、数据集类型选择、提交进入采集）；数据规划（类型规划、数据量级规划、数据来源说明）。

先明确：

- 数据用于资料整理与关联、模型训练还是智能体构建。
- 需要文本、图片还是问答对，以及各类数据的比例和规模。
- 数据来源、授权、字段规范与质量要求。
- 清洗规则、标注规范和验收标准。

这一阶段主要由本项目建设。

六个平台的项目设置、标签和处理参数可以根据部分规划要求配置，但不能替代需求文档要求的业务表单和建设流程。

例如，规划中规定“土壤含水量统一使用百分比”，之后应落实为清洗规则、标注说明和审核条件。

### 2.2 数据采集与原始语料管理

对应需求：文档资料上传、待标注数据上传、实时数据上传、语料预览、语料管理操作、语料统计分析；论文采集对应采集源管理、URL解析、采集规则配置、采集源校验、关键词组合、采集调度、采集监控。

数据入口包括文件上传、待标注条目、MySQL 数据及论文采集。

这一阶段应先保存原始资料及来源信息，再分流处理：

| 输入类型 | 后续路径 |
|---|---|
| PDF、扫描件 | 优先采用 MinerU 解析，输出交给 Easy Dataset 分块和生成问答；需要时先清洗 |
| Word、Excel 等办公文档 | 评估 Docling，补齐不满足的格式能力 |
| 已有 JSON/JSONL 问答 | 直接清洗或进入标注 |
| 独立图片 | 进入图像标注或视觉模型生成流程 |
| 数据库表格 | 接入后进行字段映射、校验和清洗 |

Easy Dataset、Label Studio、Argilla 都有自己的导入入口，但本项目仍需要统一采集、语料管理和统计入口。论文网站规则配置、采集调度及机构数据库对接，也需要独立实现。

### 2.3 文档解析

对应需求：图片数据清洗（PDF解析）、文档-PDF解析、文档-EXCEL解析、文档-WORD解析，以及论文知识库的全文解析。

当前流程优先采用 MinerU 解析 PDF；Docling 保留为其他格式或替代解析的候选。该选择依据当前体验，不代表已证明 MinerU 在所有 PDF 上都优于 Docling。

| 组件 | 在流程中的主要职责 | 下游需要得到的内容 |
|---|---|---|
| MinerU | 当前 PDF 主流程的解析工具，提取正文、版面、表格、公式及图片 | Markdown、结构化解析结果、图片与来源信息 |
| Docling | 其他格式资料或替代解析的候选，本流程不再由它承担分块 | 文档结构、内容元素、来源位置及素材 |

PDF 解析完成后，将 Markdown 及可访问的图片资源交给 Easy Dataset。结构化解析结果和来源位置由平台保留，用于后续溯源；导入时需核对图片引用和表格内容。需要清洗的语料先经过 Data-Juicer，再导入 Easy Dataset。

需要注意：

- 需求中的“图片数据清洗”和“文档 PDF 解析”明确共用 PDF 解析能力，可以共用后台服务。
- 表格、图片和公式的正确性仍需要核验。
- Docling 支持部分办公文档，并不等于完整满足需求中的旧格式、样式保留及 Excel 类型推断。

### 2.4 数据清洗与标准化

对应需求：文本-数据清洗，并支撑清洗流程、语料管理操作。

Data-Juicer 作为按需调用的后台加工工具。需要去重、脱敏、过滤或规范化时执行；无需这些处理的解析结果可以直接导入 Easy Dataset。

输入是解析结果或已有条目数据，处理包括：

- 清理 HTML、无效字符和重复内容。
- 识别并替换敏感信息。
- 按长度、内容质量等规则过滤。
- 规范字段与内容格式。
- 批量执行规则并输出统计结果。

它与解析模块的关系是：

解析模块负责读出内容，Data-Juicer 负责整理这些内容。

农业单位转换、土壤字段映射、业务异常值判定，需要配置或扩展对应规则。图片、表格和公式不能简单按普通文本清理，否则可能破坏科研信息。

### 2.5 知识片段生成

对应需求：知识片段生成。

由 Easy Dataset 承担当前流程的文档分块：导入 MinerU 解析后的 Markdown（需要时先清洗），配置分块参数，预览并检查文本块，再直接用于问题和答案生成。

这一步将长文档整理成多个可加工的知识片段，不生成摘要或答案。具体分块规则及其配置能力应结合 Easy Dataset 的实际界面核验，不因使用它分块就视为完整满足全部切片要求。

平台应统一保存片段与原文的关系，避免不同工具各自切分后失去关联。至少应保留：

- 原文标识、标题与章节。
- 片段标识及正文。
- 页码或来源位置。
- 关联图片、表格。
- 切片规则与版本。

这些信息同时服务问答生成、原文核对和知识溯源，需核对 Easy Dataset 实际保留和可导出的字段，缺少的信息由平台维护。若片段用于科研知识库，还需建立检索索引；问答生产中的分块不等于完成知识库建设。

### 2.6 问答生成与增强

对应需求：文本问答对提取、SFT问答对增强；部分支撑问答对标注、图像标注。

沿用 Easy Dataset 上一步产生的文本块，在同一个工具中生成问题、生成答案并人工修改。

典型路径是：

MinerU 解析结果 → 按需清洗 → Easy Dataset 分块 → 生成问题 → 生成答案 → 人工修改 → 增强或导出。

一般问答可先在 Easy Dataset 中人工检查和修改，再提交统一审核；需要单独评分或对候选答案排序时，再交给 Argilla 或配置后的 Label Studio，无须让每批数据依次使用全部工具。

这里有两个边界：

- 生成的问答属于待审核数据，仍需审核。
- 生成图片描述和图片问答需要调用视觉模型，并将对应图片一并传入。我们已观察到，普通文本问答不会自动附带来源图片，集成时必须明确处理图文关联。

### 2.7 人工标注与质量反馈

对应需求：问答对标注、图像标注、标注结果审核。

Label Studio 与 Argilla 位于这一阶段，存在重叠，可以按任务分工。

| 工具 | 建议承担的任务 | 典型输出 |
|---|---|---|
| Label Studio | 文本分类、实体圈选、图片区域标注，以及配置后的问答标注 | 类别、实体及位置、图片区域、人工填写结果 |
| Argilla | 问答质量评分、可用性判断、答案修改及候选回答排序 | 评分、标签、修订答案、答案优劣评价 |

例如，同一篇土壤论文：

- Label Studio 标出采样时间、深度、含水量和图像区域。
- Argilla 展示参考材料、问题与候选答案，收集专家评分和修订。

**两者都可以用于人工标注，项目可以选择一个主工作台，再补充需要的另一类标注界面。**大模型预标注仍需要连接外部模型和任务调度。

## 3. 标注之后还需要哪些模块

### 3.1 统一质量审核

对应需求：标注结果审核。

应将各工具产生的结果汇总到本项目的审核流程：

自动检查 → 人工复核 → 通过或退回 → 记录处理结果。

需要区分：

- Argilla 的“已提交”表示反馈已提交。
- Label Studio 的标注结果表示完成一次作业。
- Easy Dataset 的确认保留表示其内部数据选择。

这些状态都不能直接等同于本项目的正式审核通过和成果发布。

需求还要求“自然语言审核要点 → 生成质检代码 → 执行并展示结果”。这一完整功能需要额外建设，代码执行也需要有权限和资源限制的运行环境。

### 3.2 版本发布与共享

对应需求：热门数据集成果展示、数据集详情、数据集申请使用、版本控制、目录服务、权限管理、API服务。

审核通过后，统一平台负责：

- 保存原始资料、清洗结果、片段和标注成果之间的关系。
- 问答提取、增强后创建新版本。
- 标记发布版本，展示差异和质量信息。
- 提供目录检索、申请审批、授权下载及数据 API。

六个平台已有的数据集、导出或发布功能只能部分复用。工具内部的发布、文件导出及推送 Hugging Face，都不能替代需求中的数据集发布、权限控制和使用申请流程。

## 4. 如何连接科研助手平台

需求第 4.6 节要求的论文知识库，需要在解析和清洗结果上继续建设：

全文解析 → 提取研究背景、方法、结果和结论 → 提取概念并统一名称 → 关联相关论文 → 建立统一检索索引 → 检索、问答与分析 → 保存经过审核的成果。

| 科研助手模块 | 六个平台提供的基础 | 仍需建设的业务能力 |
|---|---|---|
| 文献摘要与信息提取 | PDF 由 MinerU 提供全文与结构；其他格式评估 Docling；Data-Juicer 按需整理内容 | 全文摘要、背景/方法/结果/结论抽取 |
| 统一检索索引与原文来源查看 | 解析器的来源位置、片段及素材关系 | 统一概念名称、论文与知识页面相互跳转、引用展示、更新日志 |
| 多篇论文综合分析 | 清洗后的论文、结构化知识及审核数据 | 综合多篇论文、比较研究结果、分析原因并生成报告 |
| 热点趋势与论文推荐 | 可供分析的文献内容和元数据 | 聚类、趋势计算、用户画像和推荐排序 |
| 知识库问答与结果保存 | 知识片段、审核后的问答 | 检索、模型回答、来源引用、归档与再次索引 |

**Easy Dataset 生成训练问答，与科研人员在线向知识库提问，是两种不同用途。**前者生产数据，后者需要检索和推理服务。

图表统计分析、方法学撰写、语言润色和 AI4S 实验设计，也需要独立的应用逻辑、专业模板和模型服务；六个平台主要为它们准备数据与知识基础。

## 5. 这些模块之间最关键的连接方式

建议由本项目提供统一管理模块，通过各工具的接口组织任务，统一记录以下关联：

| 关联 | 作用 |
|---|---|
| 原始文件 → 解析结果 | 能回到原文检查解析错误 |
| 解析结果 → 清洗结果 | 能解释删除、替换和过滤原因 |
| 清洗结果 → 知识片段 | 能追踪片段来自哪里 |
| 知识片段 → 问答/标注成果 | 能核验答案和标签依据 |
| 成果 → 审核记录 → 发布版本 | 能明确谁审核、发布了哪批数据 |
| 发布版本 → 应用或模型评测 | 能追踪应用使用的数据版本 |

文本清洗后，文字位置可能变化，需要记录修改前后的位置对应关系，并保留原文位置、实体标注和图片引用。只保存 Markdown，不能保证之后仍能准确找到原文。

模型实验室统一管理模型配置和使用权限，为问答生成、自动标注、质量检查、论文信息提取及科研助手提供模型调用服务。Argilla 的人工评分可以参与模型评测，但不能替代“模型评测”需求中自动运行、多模型比较和错误分析的完整评测流程。

## 6. 总结

当前 PDF 主流程由 MinerU 解析，Data-Juicer 按需清洗，Easy Dataset 完成文档分块、问答生成和人工修改。Docling 保留为其他格式或替代解析的候选；Label Studio 与 Argilla 按专门标注和质量评价任务选用。我们需要在这些组件之上建设统一的数据需求规划、任务调度、质量审核、版本管理、发布权限和来源追踪，再将加工结果提供给论文知识库、科研助手及模型训练评测，完成需求文档要求的全流程。
