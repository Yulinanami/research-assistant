按需求书，**最终要把文献加工成“能检索和溯源的知识资料”以及“能用于训练、评测的标注数据集”两类成果。**

PDF 转 Markdown 是中间步骤；问答 JSON 也只是最终成果的一部分。

依据主要是需求书中的“数据预处理”“数据标注”“论文资料结构化编译”（即提取论文信息并建立关联），以及“数据实体与数据架构”。

## 1. 一篇文献最终会产生的内容

| 成果 | 具体内容 | 用途 | 格式判断 |
|---|---|---|---|
| 原始文献及元数据 | 原文件、标题、作者、期刊、年份、来源和授权信息 | 文献管理、回看原文、来源核验 | 保留原文件；元数据结构化存储 |
| 解析与清洗成果 | 章节正文、表格、公式、提取图片及其对应关系 | 阅读展示、后续加工 | 需求明确提出 Markdown／JSON；图片单独保存并关联 |
| 知识片段数据集 | 切分后的正文、文档标题及上下文信息 | 知识检索、问答生成 | 建议使用 JSON／JSONL，需求未指定唯一格式 |
| 论文关键信息 | 研究背景、目的、对象、方法、实验设计、关键指标、结果和结论 | 快速阅读、比较不同论文、查找相关研究 | 结构化记录和可阅读的页面；具体存储格式待设计 |
| 问答与标注成果 | 问题、审核后的答案；图片描述、图片问答；标签及审核记录 | 人工标注、评测 | 建议使用 JSON／JSONL，按目标系统导出 |
| 检索索引与论文关联 | 概念、方法、论文、知识页面之间的关系，以及来源链接 | 检索、关联分析、知识溯源 | 数据库、检索索引、向量库及图谱中的数据 |
| 发布数据集 | 上述成果按用途组合，附带版本、元数据、权限及质量信息 | 申请使用、下载、API 服务 | 带版本的数据集 |

## 2. 用一篇农业论文举例

以下内容是模拟示例，用于说明加工目标。

论文原文包含：A组土壤含水量为20%，B组为25%。在10厘米深度采样。

### 2.1 文档解析成果：把原文读出来

得到：

- 论文标题、作者、年份等元数据。
- “材料与方法”“结果”等章节正文。
- 表格中的组别和数据。
- 图片文件及图注。
- 公式、页码及来源位置。

主要使用：MinerU、Docling。

### 2.2 知识片段：将长文献切成可检索的小段

例如：

```json
{
  "document_id": "paper-001",
  "chunk_id": "chunk-012",
  "title": "模拟土壤含水量研究",
  "section": "结果",
  "text": "A组土壤含水量为20%，B组为25%。",
  "source_page": 5
}
```

保留了文档基本信息；页码、章节和原文标识用于找到原文依据。

可以直接用于知识库检索。

### 2.3 论文关键信息：整理研究对象、方法和结果

例如：

| 信息项 | 抽取内容 |
|---|---|
| 研究对象 | 土壤 |
| 实验设计 | A、B两组对比；其他设计信息按原文提取 |
| 采样深度 | 10厘米 |
| 关键指标 | 土壤含水量 |
| 核心结果 | A组20%，B组25% |
| 研究结论 | 按论文实际结论提取，不自行推断 |
| 来源 | 原论文及对应段落、表格或页面 |

可以抽取概念、方法和材料，将它们与已有论文关联，供科研助手生成摘要、对比论文和综合分析多篇研究。

### 2.4 问答数据：作为训练或评价样本

例如：

```json
{
  "question": "B组土壤含水量比A组高多少个百分点？",
  "answer": "高5个百分点。",
  "source_document_id": "paper-001",
  "source_chunk_id": "chunk-012",
  "review_status": "通过"
}
```

```json
{
  "instruction": "B组土壤含水量比A组高多少个百分点？",
  "input": "A组为20%，B组为25%。",
  "output": "高5个百分点。"
}
```

### 2.5 图像成果：图片与描述、问答一起保存

对于论文中的图片，需求要求支持两类生成成果：

- 图片描述： 图片展示的内容。
- 图片问答： 针对图片提出问题，并给出答案。

最终需要保存图片本身及其与描述、问答的关联。

## 3. 最终数据加工成果的用途

### 3.1 供科研助手使用的知识成果

主要包含：

按章节整理的全文、图片与表格、知识片段、论文摘要、概念之间的关系和原文链接。

这些内容可供科研人员：

- 查找相关论文和段落。
- 阅读结构化摘要。
- 比较不同论文的方法与结果。
- 提问并查看原文依据。
- 将高质量分析和问答归档为新的知识页面。

### 3.2 供模型训练、评测使用的数据成果

主要包含：

审核后的文本问答、图片描述与问答、人工标签，以及按任务收集的质量评价。

按实际任务导出相应格式，并保留独立版本。

需求书明确提出 SFT 问答增强和模型评测，但没有明确规定必须进行模型训练，也没有规定必须生产比较答案优劣的排序数据；这些应由具体使用场景决定。

## 4. 对这六个平台的最终定位

| 平台 | 它帮助生产的主要成果 |
|---|---|
| MinerU、Docling | 文档结构、正文、表格、公式、图片及来源信息 |
| Data-Juicer | 清洗、去重、脱敏和标准化后的语料 |
| Easy Dataset | 从文献片段生成的待审核问答，以及改写或扩充后的问答数据 |
| Label Studio | 人工分类、实体、图像等标注成果 |
| Argilla | 问答评分、可用性判断、修改后的答案等评价结果 |
| 本项目统一平台 | 将这些成果组织为带来源、审核记录、版本和权限的知识库与发布数据集 |

文献加工的终点，是形成“可追溯的科研知识”和“审核后的高质量数据集”。Markdown、JSON 和图片文件用于保存这些内容；真正需要交付的是里面的结构化内容，以及来源、质量、版本和使用权限。
