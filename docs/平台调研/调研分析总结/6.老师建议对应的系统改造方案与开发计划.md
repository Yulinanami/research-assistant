# 老师建议对应的系统改造方案与开发计划

整理日期：2026-10-21。

依据：老师本次提出的建议；用户提供的《招标需求原文.xlsx》中“数据知识加工平台功能”工作表；仓库需求规格说明书、工作计划、既有调研文档；当前 `demo/web` 代码。本文是改造建议与开发清单，不表示这些能力已经实现。

原表共 35 个编号功能，分布在 Excel 第 2—43 行。下文保留原功能名与编号，以便核对；老师提出的首页、项目工作空间、图片整体分类等调整另行注明。Excel 中“重要性”与本文开发优先级是不同字段，不能相互替代。本次不修改招标原表及已有应用代码。

## 1. 整体调整方向

系统按“发现数据 → 打开项目建设数据 → 管理成果 → 申请共享”组织。

1. 首页放在登录前的外部入口，展示公开成果并引导登录；登录后默认展示工作台，工作空间内不重复设置首页菜单。
2. 工作台负责最近项目入口、任务记录、待办及统计；打开项目后进入“数据加工”的项目工作空间。
3. “数据加工”保留为一级业务大类，进入后先选择或打开项目，再开展加工；中间成果在项目内查看、继续加工，不默认跳转到治理共享页面。
4. “数据标注”作为统一入口，容纳知识片段、问答生成与增强，以及人工分类、实体标注和图像标注等不同处理逻辑。
5. 治理共享面向权限范围内的全部数据集；列表以数据集为单位，版本历史收进详情。
6. 右上角设置集中维护模型、解析参数、提示词与任务默认配置；创建任务时选择输入、模板和少量必要参数。

### 1.1 先统一业务对象

| 对象 | 含义 | 与其它对象的关系 |
| --- | --- | --- |
| 项目 | 一次数据建设工作的空间，记录目标、成员、资料、任务和配置 | 一个项目可建设多个数据集 |
| 原始资料 | 上传文件、数据库导入结果、已有待标注条目 | 归属项目，保留原始输入 |
| 中间成果 | 解析正文、清洗结果、知识片段、模型预测等 | 关联输入、任务和配置，可作为后续输入 |
| 数据集 | 有稳定编号、字段定义、责任人和用途的数据集合 | 有归属项目和所有者，可有多个版本 |
| 数据集版本 | 某次数据内容和标注结构的快照 | 关联来源成果及父版本 |
| 发布记录 | 将一个审核通过的版本用于目录展示和共享 | 指向固定版本，审批及 API 也绑定该版本 |

当前代码中 `dataset.project` 只是文字字段，`activeDataset` 同时承担全局选择和加工上下文，没有独立的项目实体。建议增加 `projects`、`activeProjectId`，为数据集、资料和任务补充 `projectId`；数据集补充稳定的 `ownerId`。演示角色不能代替正式用户身份。

## 2. 页面与菜单结构

### 2.1 推荐结构

```text
未登录入口
└─ 外部首页
   ├─ 平台介绍与公开数据集推荐
   └─ 登录 → 工作台

登录后工作空间
├─ 工作台
│  ├─ 我的项目 / 最近项目 / 新建项目
│  ├─ 加工任务、待办、运行情况
│  └─ 数据与任务统计
├─ 数据加工（保留一级大类）
│  ├─ 项目列表：选择项目 / 新建项目
│  └─ 当前项目工作空间
│     ├─ 项目概览、资料、任务及中间成果
│     └─ 需求规划 → 语料接入 → 预处理 → 清洗 → 数据标注 → 质量审核 → 成果发布
├─ 加工任务
│  └─ 跨项目任务记录、项目与状态筛选、预设流程；查看成果回到所属项目
├─ 我的数据集
│  └─ 所有本人拥有的数据集，可定位所属项目
└─ 数据治理与共享
   ├─ 数据目录（本区域第一个入口）
   ├─ 数据广场
   ├─ 数据标准与字典
   ├─ 成果审核
   ├─ 使用申请与审批
   ├─ 权限管理
   └─ 数据服务

右上角：设置
├─ 模型配置 / 模型试用 / 模型评测
├─ 解析配置
├─ 清洗配置与流程模板
├─ 标注模板 / 受众模板 / 提示词模板
└─ 默认导出配置

从工作台或数据加工项目列表打开项目后，统一进入数据加工工作空间
├─ 项目名称、返回工作台、项目概览
├─ 当前项目的数据集与建设目标
└─ 顶部加工流程 + 当前步骤的纵向内容卡片
```

“数据加工”和“数据治理与共享”保留为并列的业务大类。工作台提供快捷入口；加工页面固定当前项目，阶段操作通过顶部流程进入。用户直接点击“数据加工”时，展示项目选择或已打开的项目工作空间。

全局页面移除“必须先选择某个数据集”的前提。治理共享可以按项目、所有者、类型和状态筛选，但默认查询权限范围内的全部数据集。

### 2.2 三个数据入口的区别

| 入口 | 展示范围 | 主要动作 |
| --- | --- | --- |
| 我的数据集 | 本人拥有的全部数据集，包含草稿与建设中的数据集 | 查看、打开所属项目、继续建设 |
| 数据目录 | 本人拥有的，以及使用申请已审批通过的数据集 | 查阅可用版本、下载获授权版本、查看服务 |
| 数据广场 | 当前用户可以发现的、已发布且允许展示的数据集 | 搜索、预览、申请使用 |

三个入口共用数据实体、权限规则和详情组件，只改变查询范围。申请中的数据不提前进入“已获授权”集合；公开可发现也不自动等于允许下载。首页推荐只引用广场中当前用户可见的成果。

### 2.3 菜单视觉方案

| 方案 | 全局布局 | 打开项目后的布局 | 适用情况 |
| --- | --- | --- | --- |
| A，推荐 | 首页位于登录前；登录后侧栏为工作台、数据加工、加工任务、我的数据集、数据治理与共享；右上角设置与退出登录 | 进入“数据加工”后，顶部显示项目上下文与七阶段流程，正文采用纵向卡片；不再增加项目侧栏菜单 | 项目上下文清楚，适合本次整体调整 |
| B，改动较少 | 保留现有全局侧栏及“数据加工”大类，增加首页、工作台、我的数据集并重排共享菜单 | 在数据加工内打开项目，固定项目名称和返回按钮 | 沿用现有外壳，减少第一轮布局改动 |
| C，任务较多 | 顶部全局导航，保留“数据加工”和“数据治理与共享” | 数据加工内左侧项目资料树，中央加工卡片，右侧任务进度与下一步 | 高频操作方便，但需要更大的屏幕空间 |

推荐 A；正文继续使用此前确定的“方案 C：纵向流水线卡片”。这里的菜单方案与正文布局分别选择，不改变已经确认的七阶段顺序。

## 3. 项目内的数据加工流程

```mermaid
flowchart LR
  A[1 需求规划] --> B[2 语料接入与解析]
  B --> C[3 预处理]
  C --> D[4 清洗]
  D --> E[5 数据标注]
  E --> F[6 质量审核]
  F --> G[7 成果发布]
  G --> H[全局目录与数据广场]
```

| 阶段 | 页面职责 | 交付下一阶段的内容 |
| --- | --- | --- |
| 1 需求规划 | 数据集用途、类型、量级、质量要求、字段与标签模板 | 数据集建设目标与结构 |
| 2 语料接入 | 上传、条目导入、数据库接入；按文件类型解析并预览 | 原始资料引用和可用解析内容 |
| 3 预处理 | 确认输入、字段映射、类型检查、缺失信息检查 | 可被清洗或标注步骤使用的数据结构 |
| 4 清洗 | 文本清洗、图片清洗；选择流程、试运行、执行、查看保留与过滤原因 | 带来源和处理配置的中间成果 |
| 5 数据标注 | 选择任务类型及模板，执行模型辅助或人工处理 | 带标注内容的数据集版本或待复核结果 |
| 6 质量审核 | 项目内查看检查结果、修改问题、提交人工审核 | 有审核状态与意见的成果版本 |
| 7 成果发布 | 填写发布说明、选择版本、可见范围和共享方式 | 关联固定版本的发布记录 |

解析继续放在语料管理；第 3 步负责输入准备，不再重复提供解析入口。格式已符合要求时，可以跳过预处理检查中的可选项或清洗，保留跳过记录。已有标注条目、图片分类任务可以直接选择相应标注路径，不强制经过知识切片和问答生成。

### 3.1 中间成果留在项目内

当前 `ProcessView.vue` 的任务成果按钮会跳转全局 `versions` 页面。改造后默认打开项目内的“任务结果”抽屉或详情页，提供：

- 查看输入、输出、执行日志和配置快照。
- 预览文本、结构化条目、图片或标注结果。
- 使用本次结果继续清洗、创建知识片段、生成问答或进入人工标注。
- 将选定结果保存为数据集版本，并继续复核。

只有用户明确进入成果发布或全局管理时才切换到治理共享上下文。项目审核入口和全局审核台操作同一份审核记录，不重复建立两套审批流程。

### 3.2 加强下一步引导

| 当前动作完成 | 默认下一步按钮 | 允许的其它动作 |
| --- | --- | --- |
| 创建项目及建设目标 | 接入资料 | 保存草稿 |
| 上传文档 | 解析文档 | 预览原文件、继续上传 |
| 解析成功 | 确认预处理输入 | 重新解析 |
| 预处理确认 | 进入清洗 | 直接创建标注任务 |
| 清洗成功 | 使用本次结果创建标注任务 | 查看过滤原因、调整规则重跑 |
| 模型生成或预标注完成 | 人工复核 | 继续增强、创建修订版本 |
| 人工标注完成 | 提交质量审核 | 保存草稿 |
| 审核通过 | 发布成果 | 留作项目内部使用 |
| 使用申请通过 | 查看获授权版本 | 下载或查看服务说明 |

按钮应携带项目、目标数据集和输出成果引用。执行失败时展示原因与重试入口，避免引导用户继续使用失败或已失效的结果。

## 4. 数据标注的含义与任务类型

按老师建议，把“知识片段与问答生成”和现有“数据标注”合并为一级“数据标注”。这里是统一的数据建设入口，内部明确区分自动生成、模型预标注和人工标注，界面展示每一种结果的来源与确认状态。

Label Studio 的标注在项目中进行，通过模板配置任务类型、输入字段和标签；本项目可借鉴这种交互组织方式。[官方配置说明](https://labelstud.io/guide/setup.html)

| 数据类型 | 建设或标注方式 | 示例结果 | 第一轮原型范围 |
| --- | --- | --- | --- |
| 文本 | 知识片段生成 | 正文片段、来源页码或段落信息 | 保留并纳入统一入口 |
| 问答 | 问答生成、问答增强、人工修改与质量打标 | 问题、答案、参考材料、评分、修订记录 | 优先完善 |
| 文本 | 整体分类 | 研究背景、实验方法、研究结果 | 增加模板与分类操作 |
| 文本 | 实体标注 | 采样时间、采样深度、指标值及文本位置 | 后续迭代 |
| 图片 | 整体分类，支持单选或多选 | 健康叶片、病害叶片，或多种病害标签 | 优先增加 |
| 图片 | 区域框选 | 病斑框及类别、图表区域 | 保留并完善当前框选能力 |
| 图片 | 图片描述、图片问答 | 描述文本或与图片关联的 QA | 合并到相应模板 |
| 多模态及其它 | 音频、视频、分割等 | 取决于模板与导出转换 | 作为扩展候选，不由工具支持范围直接推导为本项目承诺 |

图片整体分类给整张图片选择标签，不需要画框；模型预测类别是建议结果，需要记录置信度及人工确认状态。训练图片分类模型是另一项工作，不能因新增分类标注入口就视为已具备模型训练能力。Label Studio 提供了独立的整图分类模板。[官方图片分类模板](https://labelstud.io/templates/image_classification)

### 4.1 区分三种“标签”

| 名称 | 作用对象 | 示例 | 使用位置 |
| --- | --- | --- | --- |
| 数据集标签 | 整个数据集 | 土壤、作物病害、问答训练 | 我的数据集、目录、广场检索 |
| 样本标注标签 | 一条文本、图片或区域 | 健康叶片、病斑、实验方法 | 标注任务、训练数据导出 |
| 质量标签 | 样本或成果版本 | 可用、需修改、不可用 | 复核、质量统计、导出筛选 |

标签模板保存名称、解释、颜色、是否多选、适用任务和版本。模板被任务引用后保存快照，后续修改模板不改变旧任务的标签含义。

### 4.2 格式质量要求

把当前自由填写的“JSON、Markdown”拆成四项：数据用途、任务类型、记录结构、导出文件格式。

Easy Dataset 的官方导出文档列出 JSON、JSONL、Excel 文件格式，以及 Alpaca、ShareGPT 和自定义字段风格；文件格式与记录结构应分别选择。既有调研文档中提到的 CSV 不作为本轮已核实的 Easy Dataset 导出事实。[官方导出说明](https://docs.easy-dataset.com/shu-ju-ji/shu-ju-ji-dao-chu)

| 目标数据 | 记录结构要求 | 导出策略 |
| --- | --- | --- |
| 单轮训练问答 | 问题与答案完整，可映射 `instruction/input/output` | 优先 JSON、JSONL；提供 Alpaca 映射 |
| 多轮对话 | 对话顺序、角色和消息内容完整 | 提供 ShareGPT 等目标结构的适配与校验 |
| 知识片段 | 文本、来源、片段编号与元数据 | JSON、JSONL、Markdown，按用途选择 |
| 图片整体分类 | 图片引用、类别编码、标签模板版本 | 原始标注 JSON；按目标训练框架转换 |
| 图片区域标注 | 图片尺寸、区域坐标、类别及标注关系 | 原始 JSON；目标检测格式按任务适配 |

Label Studio 的导出格式与标注类型有关，部分格式仅包含标注而不包含原始数据；原生图片框 JSON 使用相对图片尺寸的百分比坐标。导出前需要验证资源引用和坐标转换，不能只修改文件后缀。[官方导出说明](https://labelstud.io/guide/export.html)

## 5. 数据字典与业务字段结合

数据字典承担“定义字段及其取值规则”的职责。用户创建字段后，应能在数据集编辑、样本标注或导出映射中实际引用。

| 字段示例 | 字段作用范围 | 规则 | 使用环节 |
| --- | --- | --- | --- |
| `dataset_code`，数据集编号 | 数据集元数据 | 平台生成、唯一、只读，编码规则统一维护 | 新建、目录检索、版本关联、服务 |
| `crop_type`，作物类型 | 数据集元数据 | 选择作物字典中的值 | 建设需求、目录与广场筛选 |
| `sampling_depth`，采样深度 | 样本或业务记录 | 数值，单位为厘米，范围按业务配置 | 表格字段映射、清洗校验、标注表单 |
| `disease_class`，病害类别 | 图片样本标注 | 类别编码、含义、单选或多选 | 图片整体分类、结果统计与导出 |
| `soil_moisture`，土壤含水量 | 样本或业务记录 | 类型、单位及允许范围由对应业务定义 | 结构化导入、人工复核、质量检查 |
| `quality_label`，质量标签 | 标注记录 | 可用、需修改、不可用等枚举 | 复核与导出筛选 |

每个字段定义包含：字段编码、中文名称、解释、作用范围、数据类型、单位、枚举来源、必填条件、校验规则及版本。数据集元数据标记与逐条样本标注分开保存；例如“这个数据集研究水稻”与“这张图片属于稻瘟病”是不同层次的信息。

第一轮先打通“创建字段 → 绑定数据集或标注模板 → 表单填写 → 必填和类型校验 → 目录筛选或导出”，后续再扩展业务语义检查。内置身份、编号和版本关联等系统字段不允许被同名自定义字段覆盖。

## 6. 设置、模板与任务配置

### 6.1 配置的归属

| 位置 | 放什么 | 任务页如何使用 |
| --- | --- | --- |
| 右上角设置 | 模型连接、解析默认值、清洗配置、受众与提示词、标签模板、导出映射 | 选择模板并查看摘要 |
| 项目设置 | 当前项目绑定的模板、默认模型、默认字段、流水线 | 打开项目时自动载入 |
| 本次任务 | 输入资料、目标数据集、本次受众及必要覆盖参数 | 创建前确认，保留本次快照 |

参数取值顺序建议为：本次覆盖值 → 项目配置 → 用户默认配置 → 系统内置值。配置维护入口移到设置页面后，创建任务仍需显示“本次实际使用什么”，并提供编辑本次参数或前往设置的入口。

模型使用与评测从加工菜单移到右上角设置，包含模型配置、试用和评测三个子页。共享模板的可修改范围与用户个人配置分别处理。

### 6.2 受众放在模板前面

问答生成和问答增强的配置顺序统一为：

```text
选择输入 → 目标受众 → 任务模板 → 提示词预览与修改 → 模型摘要 → 执行
```

受众模板示例：农业科研人员、基层农技人员、学生或初学者。模板应说明知识深度、语言风格、解释要求和示例。选择受众后自动填充提示词，并允许修改；如果用户已修改提示词，再切换受众时需明确选择保留或替换，避免丢失输入。最终保存的是实际提示词与模板版本。

### 6.3 清洗配置提供两种方式

| 方式 | 操作 | 要求 |
| --- | --- | --- |
| 简易配置 | 选择预设、增删算子、排序、修改阈值、试运行 | 可解释每一步处理内容与过滤原因 |
| 完整配置 | 编辑或导入目标版本的 Data-Juicer YAML | 校验语法、算子、参数、字段及输入输出映射 |

两种方式使用同一份规范化配置。简易编辑器只能无损转换其支持的配置；遇到尚不支持的算子或高级设置时保留完整配置，不能在切换模式时静默丢弃。

先提供“通用文本规范化”“脱敏与质量筛选”“科研正文去重”等预设。每个预设记录适用数据、算子顺序、参数和 Data-Juicer 版本；预设效果需用本项目样本验证。Data-Juicer 官方提供配方配置和流水线执行方式，适合承担清洗执行；跨解析、标注、人工审核和发布的总流程由本平台编排。[官方快速开始](https://github.com/datajuicer/data-juicer/blob/main/docs/tutorial/QuickStart.md)

### 6.4 任务名称与预设流水线

任务名称默认采用“项目简称 · 操作类型 · 输入批次 · 时间 · 短编号”，允许重命名；列表同时显示输入摘要、目标数据集、发起人、状态和输出数量，避免所有记录仅叫“文本清洗任务”。

自动流程第一轮支持有顺序的步骤，不急于实现任意分支画布：

```text
解析成功 → 输入准备 → 清洗成功 → 生成或预标注 → 等待人工复核
```

完整执行需要保存流程模板和执行实例，记录每个节点的输入、输出、配置版本和任务编号。仅在前一步成功且输出有效时启动下一步；失败暂停，支持从指定步骤重试。重试应避免重复创建下游任务。人工复核和发布设置明确的人工确认节点。

当前演示用浏览器定时器执行任务，刷新会中断。正式的耗时流程需后端任务队列、持久化状态和重试机制；Data-Juicer 的恢复能力也要按所选版本与执行器验证，不能直接等同于整个平台已具备恢复能力。[官方处理与恢复说明](https://datajuicer.github.io/data-juicer/en/main/docs/ProcessData.html)

## 7. 治理共享与版本呈现

治理共享默认按数据集聚合列表，数据目录放在菜单首位。每个数据集只出现一张卡片或一行，展示：编号、名称、所属项目、所有者、标签、可见的当前版本、条目数、更新时间和权限状态。

```text
土壤科研问答数据集                       查看详情
编号：DS-2026-0001  当前可用版本：v1.0.0
标签：土壤环境 / 科研问答

进入详情：
  介绍 | 数据预览 | 文件 | 字段与标签 | 使用权限
  ▸ 版本历史（默认折叠，点击展开）
      V3 草稿          仅建设人员可见
      V2 审核中        仅相关人员可见
      V1 已发布        按版本授权查阅与下载
```

广场的默认版本使用可见的发布版本；目录显示当前用户实际拥有或获授权的版本，不直接展示数据集的最新草稿。历史版本只显示当前用户有权查看的部分。对 V1 的授权不自动扩大为对 V2 的授权。共享详情提供“申请使用此版本”；通过后才启用对应下载。

项目内保留完整的中间成果和建设版本历史；全局列表不把解析输出、清洗输出与发布数据集混在一起。我的数据集、目录、广场及首页推荐统一使用数据集详情与聚合规则。

### P0：先解决结构和上下文

1. “图片数据清洗”的原表描述与 PDF 解析重复：保留原表名称及位置，图片去重、模糊筛选等作为独立建设项验证，不据此宣称已满足原表。

5. “数据版本折叠”是列表与详情呈现调整，不删除历史内容，也不把旧版授权扩大到所有版本。
