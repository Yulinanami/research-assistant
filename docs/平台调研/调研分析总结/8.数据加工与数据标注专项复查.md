# 数据加工与数据标注专项复查

复查日期：2026-10-22，第二轮。

本轮按“需求规划 → 语料接入与解析 → 预处理 → 清洗 → 数据标注 → 项目成果”检查全部数据加工链路，重点检查标注的输入、模板、工作副本、草稿、模型建议、人工确认和导出。检查包含源码分析、Vue 表单运行验证及任务调度回归。没有接入真实解析器、模型、Data-Juicer 或 Label Studio 服务。

本轮修改加工与标注逻辑。`ResultsView.vue` 为共用组件，本轮仅增加项目内导出范围，并统一生效答案的读取；没有调整治理的权限、审批、目录和发布规则。

## 1. 结论

菜单和任务入口已较完整，但上一轮测试未覆盖的表单保存行为仍有数据一致性问题。本轮重点修复了模板外标签被接受、切换丢标注、模型建议覆盖人工结论、导入成果被原地改写、输入范围串用及图片导出缺资源等问题。

本地人工分类、问答复核和矩形框选的闭环已加强；真实自动生成、多模态资源管理、复杂任务模板与业务字典仍未完整交付。不能将“有入口”或“模型返回模拟样例”计为真实标注能力。

## 2. 全部加工环节复查

| 环节 | 本轮检查与处理 | 当前边界 |
| --- | --- | --- |
| 项目及需求规划 | 检查项目/数据集切换、格式与质量要求、元数据编辑；保留字典已移除字段的历史元数据，避免编辑时静默丢失 | 样本业务字段、单位和范围规则尚未贯穿全流程；规划可选格式与实际导出能力尚需统一 |
| 语料接入与解析 | JSON 编辑先验证再形成新导入修订；原资料修订与解析成果关联；二进制文档与图片不再作为普通文本修改 | PDF/Word/Excel 解析仍模拟；数据库、SDK、通用 CSV 字段映射待接入 |
| 预处理 | 过滤正文不进入输入；旧修订解析不作为新资料的默认结果；混合类型分别处理，多份问答不再隐含只复核一份 | 尚无完整的字段映射、必填、类型和业务检查报告 |
| 数据清洗 | 图片清洗按用户排列的规则顺序执行；传递原资料编号；明确图片标准化仍为目标信息模拟 | 未执行真实图片转换或 Data-Juicer 配方；没有异步服务、取消和断点恢复 |
| 数据标注 | 分类约束、模板快照、工作副本、人工与模型分离、输入隔离、草稿冲突检查、图片资源和坐标校验 | 详见第 3—5 节 |
| 项目成果与导出 | 原生分类导入成果进入正确编辑器；修订答案与预览一致；新增“全部未过滤记录 / 仅人工确认可用”范围 | Excel、自定义字段、标注配置与资源清单打包、多框架转换仍需开发 |
| 加工任务与预设流程 | 输入在启动时冻结；空内容、过滤内容、错误任务类型、无效模型进入失败状态 | 任务仍依赖当前浏览器；跨账号权限及服务端调度不属于已交付能力 |
| 设置与模板 | 在分类开始时复制模板，设置后改不会直接改变当前任务的类别；模型下架后不能执行对应任务 | 个人、项目、任务配置继承及真正的模型评测尚未接入 |

## 3. 数据标注逐类检查

| 建设方式 | 已验证或处理的内容 | 能力状态 |
| --- | --- | --- |
| 知识片段 | 本地切片，逐条来源和输入快照；不使用空或已过滤正文 | 本地可执行；不等同于人工语义标注 |
| 问答生成 | 检查文本输入和已上架模型，结果仍带有明确的模拟边界 | 入口与任务校验可用，推理未接入 |
| 问答增强 | 只接受有未过滤问答的成果；保留原问答与修订答案 | 本地演示逻辑，真正的受众改写需模型服务 |
| 文本分类 | 单选/多选约束、模板内标签、快照、草稿及工作副本 | 本地人工分类可执行 |
| 图片整体分类 | 同上；选择某份输入不混入无关导入记录；原生导入标签可续标 | 本地人工分类可执行；远程图片资源未完整接入 |
| 图片区域框选 | 支持可读取的原图、导入图片和保留成果；保存图片内容、来源、百分比坐标及可读取的尺寸 | 本地矩形框选可执行；无目标负样本与复杂区域任务待补 |
| 图片描述 | 检查输入必须含图片，拒绝文本冒充图片 | 输出仍模拟 |
| 图片问答 | 检查输入必须含图片，拒绝空及已过滤输入 | 输出仍模拟，真实图像依据与推理需联调 |
| 问答人工复核 | 当前生效答案、质量枚举、评分、混合记录保留、模型建议分离及保存前冲突检查 | 本地人工复核可执行 |

分类标签描述“样本属于哪类”，质量标签表示“样本是否可用”，模型建议表示“待人工判断的预测”。这三者分别保存，模型建议不会自动变成人工确认结果。

## 4. 本轮发现并修复的问题

难度指本地原型修复难度。优先级以数据错误风险排序，不代表正式服务交付难度。

| 编号 | 问题及触发条件 | 修复结果 | 难度 / 优先级 |
| --- | --- | --- | --- |
| A01 | 导入或恢复的分类标签不属于当前模板，仍可提交 | 保存检查模板内标签、单选/多选及重复标签；提交另外检查是否完成 | 低 / P0 |
| A02 | 切换模板直接清空已标标签；任务运行期间修改设置会改变当前标签含义 | 切换前确认；开始分类即保存独立模板快照 | 中 / P0 |
| A03 | 切换建设方式、数据集或页面会丢失未保存标注 | 正常离开组件时保留按演示身份、数据集和方式区分的工作副本；切换输入可取消 | 中 / P0 |
| A04 | 质量标签可随意改名，已有记录可能留在不再定义的标签中 | 明确质量标签含义；保存枚举快照；检查未定义质量标签、空回答及无效评分 | 中 / P0 |
| A05 | 自动标注把已有人工标签与评分清空 | 只增加模型建议与模型编号，保留人工标签、评分和修订答案；不建议已过滤记录 | 低 / P0 |
| A06 | 人工复核模型建议版时，可能直接改写原始问答草稿 | 保存为独立人工复核草稿，来源指向建议版，原始成果与预测成果均保持 | 中 / P0 |
| A07 | 混合成果中非问答和已过滤记录也进入问答复核 | 只呈现可复核问答；保存时合并回原位置，保留其它记录 | 中 / P0 |
| A08 | 图片框选输出仅存本地图片编号，导出后难还原 | 保存实际图片引用、来源、坐标单位和可读取的自然尺寸；校验有限值、范围与类别 | 中 / P0 |
| A09 | 原生分类 JSON 导入后，“编辑内容”可能进入普通文本编辑，或直接覆盖导入源版本 | 识别原生分类结构；进入对应编辑器；另建人工标注草稿 | 中 / P0 |
| A10 | 恢复旧工作副本后保存，可能覆盖其它操作已修改的草稿 | 保存前比较载入时的输入内容；冲突时拒绝覆盖，要求重新打开成果 | 中 / P0 |
| A11 | 明确交接某份原资料时，分类仍混入其它导入条目；交接不匹配时回退无关原图 | 严格限定交接编号；支持汇集多个明确选中成果；无匹配输入时显示空状态 | 中 / P0 |
| A12 | 混选文本与图片，或选择多份问答后，下一步只处理部分内容 | 预处理要求按同一种类型处理；人工复核要求一次选择一个成果 | 低 / P0 |
| A13 | 任务执行中修改输入，导致本次结果来自启动之后的内容 | 启动时冻结来源与成果快照，执行和记录均使用该快照 | 中 / P0 |
| A14 | 图片生成任务可以接受文本；过滤问答或无效模型仍可能产生模拟成功结果 | 调度层检查任务类型、有效输入和已上架模型，错误进入失败记录 | 中 / P0 |
| A15 | 修改资料后仍默认使用旧解析或旧导入结果 | 引入来源修订号并匹配解析/导入成果；JSON 编辑校验失败不修改资料 | 中 / P0 |
| A16 | 图片清洗页面允许排序，但实际执行固定顺序 | 图片演示清洗也按步骤排列执行，并保留原资料关系 | 中 / P1 |
| A17 | 问答训练导出没有人工质量筛选，容易混入不可用和未复核记录 | 项目导出增加质量范围；切换到 Alpaca/ShareGPT 时默认仅人工“可用”；可主动改为全部未过滤记录 | 中 / P1 |
| A18 | 修改规划元数据时，字典不再显示的历史字段被整份替换而丢失 | 合并新填写字段，保留历史元数据 | 低 / P1 |

A03 的工作副本用于正常页面切换，不是浏览器刷新或崩溃后的实时自动保存承诺。重要修改仍应点击“保存草稿”。已提交、已通过或已发布的成果再次修改时继续创建新草稿。

图片区域坐标以实际图片元素的边界计算，排除容器边框造成的偏差；指针起点限制在图片范围内。此项经过源码检查与数据校验测试，尚未完成真实浏览器的拖动交互验收。

## 6. 验证记录

- 自动化测试从 37 项增至 54 项，全部通过。其中 7 项运行真实 Vue 单文件组件的 setup、watch 和保存逻辑，覆盖分类约束、取消切换、混合问答复核、模型建议独立保存、框选资源、工作副本恢复及草稿冲突。
- 任务调度回归覆盖模型建议保留人工结果、输入冻结、错误类型、空输入、过滤问答、无效模型及 JSON 修订；纯逻辑回归补充严格输入范围、质量导出、区域校验、来源修订及图片清洗顺序。
- `npm.cmd run build` 通过。生产包仍有大块提示，未进行按需拆包或容量测试。
- 本轮没有真实浏览器端到端测试。组件运行测试不等同于图片拖动、布局、文件下载与 IndexedDB 刷新恢复的浏览器验收。
- 未进行真实模型、Data-Juicer、解析器或 Label Studio 联调，也未进行安全渗透测试。

浏览器验收顺序建议：V7 导入与续标 → 分类切换与恢复 → 问答预标注及人工复核 → 图片框选和 JSON 导出 → 两数据集来回切换 → 原资料修订后重跑 → 按质量范围导出。发现新的交互失败后再补相应修复。
