## 2. 具体复现和影响

### B01：切换选项后，本页任务与结果消失

- 复现：知识片段执行完成，切换到问答生成，再切回知识片段；图片描述执行后切换其它生成方式也有相同行为。
- 结果：知识片段本页输出数量从 1 变为 0；底层任务记录仍为 1。本问题是页面丢失本次任务关联，没有删除已保存成果。
- 原因：`AnnotationWorkbench.vue` 的 mode watcher 每次切换都把 `taskIds` 清空。
- 影响：用户以为任务未保存或未执行，需要离开当前页去加工任务或项目成果找回。
- 优先级：P1。

### B02：用户选择的输入资料被重置

- 复现：知识片段中主动选择“乙资料”，执行后切换问答生成，再切回来。
- 结果：所选输入从“乙资料”变成“甲资料”，即候选列表第一份。
- 原因：mode watcher 按最初进入页面时的 handoff 重建选择；匹配失败时直接取第一项，没有各方式独立的输入状态。
- 影响：再次执行可能处理错资料，尤其是连续创建不同类型任务时。
- 优先级：P1。

### B03：切换分类方式后，旧输入范围造成假空状态

- 复现一：从文本清洗结果进入数据标注，再点击图片分类；当前数据集同时有原始图片。
- 复现二：从图片清洗结果进入数据标注，再点击文本分类；当前数据集同时有原始文本。
- 结果：分类区显示 0 条记录，但当前数据集有对应原始资料。分类页没有重新选择原始输入的控件。
- 原因：新的任务类型继续使用旧 pipeline 的输入编号，严格过滤后为空；界面未提供解除该范围或选择其它资料的操作。
- 影响：用户会看到“暂无资料”，并误以为上传失效。不能靠重新放开过滤解决，否则会再次发生串用输入。
- 优先级：P1。

### B04：空工作副本遮住后来导入的新资料

- 复现：无图片时进入图片分类，离开接入图片，再返回图片分类；文本分类和问答人工复核也分别验证。
- 结果：分类函数已有 1 条可用记录，分类表单仍显示 0 条；问答复核已有 1 个可选版本，当前复核记录仍为 0。
- 原因：离开时缓存了空数组；返回时只比较输入范围等条件，就用空缓存覆盖重新载入的内容。
- 影响：最常见的新建数据、接入、回到标注路径会卡住。
- 优先级：P1，建议先修。

### B05：修订旧分类成果时，父版本关联到无关新成果

- 复现：准备一个旧的已发布图片分类版本，再创建一份新的问答版本；回到旧分类版本编辑标签并保存。
- 结果：新分类草稿的 `parentVersionId` 指向后来新建的问答版本，而不是实际编辑的旧分类版本。
- 原因：分类保存传入的是记录原始资料编号；`createVersion` 找不到对应数据集父版本，就回退到当前数据集最新版本。
- 影响：版本关系和“基于哪个版本创建”的说明错误，后续追溯、比较与审核依据会混乱。
- 验证范围：本轮直接复现图片分类；同一分类组件供文本分类使用。
- 优先级：P1，建议先修。

### B06：旧框选成果的图片快照被当前来源覆盖

- 复现：建立图片 A 的框选成果，保留图片 A 和旧框；将同一来源引用的内容改为图片 B，再打开旧框选成果。
- 结果：表单引用图片 B，框仍来自 A。运行检查中 `showsOriginal=false`、`showsChangedSource=true`，旧框数量仍为 1。
- 原因：图片列表先放保存的图片，后放当前输入；同一个编号进入 Map 时，当前输入覆盖了历史快照。
- 影响：历史成果出现图片与标注错配。
- 复现条件：本轮通过内存样本模拟同一来源内容更新；没有把它描述成已完成的浏览器上传操作。
- 优先级：P1；正式支持来源替换前必须修复。

### B07：细小框选无提示地消失

- 复现：运行框选指针结束处理，区域宽 0.8%、高 10%。
- 结果：区域没有加入记录，数量仍为 0。宽或高等于 1% 时同样不会保存。
- 原因：`pointerUp` 固定要求宽和高同时大于 1%，没有提示或可配置阈值。
- 影响：小病斑、细线、小图表元素等有效区域可能无法标注；用户容易以为鼠标拖动失效。
- 验证范围：指针处理函数的运行复现，未做真实鼠标拖动验收。
- 优先级：P2。

### B08：图片描述和图片问答的输出缺少原图

- 复现：分别用图片 A 执行图片描述、图片问答，读取输出，并调用原始结构导出。
- 结果：描述输出 1 条，含图片的条目为 0；图片问答输出 3 条，含图片的条目为 0；两者导出后仍都没有图片。
- 原因：图片描述只构建描述文本；图片问答直接复制纯文本 QA 样例。版本级 `sourceId` 仍在，但普通记录导出不携带该来源的图片资源。
- 影响：在原项目里还能通过版本来源查找原图，导出后无法独立组成图文描述或图像问答数据集。
- 优先级：P1。即使模型仍为模拟，也应保留图文结构和来源关系。

### B09：模型辅助读取旧答案，忽略未保存的人工修订

- 复现：在问答人工复核中填写修订答案，不保存，直接点击自动标注。
- 结果：当前表单含有修订内容，但新任务的 `inputSnapshot.records` 中没有这份修订。
- 原因：自动标注只传当前版本编号，调度器读取持久化版本，未采用表单工作副本，也未提示先保存。
- 影响：用户看到的答案和模型辅助实际处理的答案不同。
- 优先级：P1。

### B10：人工复核空状态的“生成问答”按钮不切换方式

- 复现：没有问答成果时进入问答人工复核，触发空状态中的“生成问答”。
- 结果：仅发出跳转 `generation` 的事件，工作方式仍是“问答人工复核”。当前页面本来就在 generation 路由，页面没有因此重新创建。
- 原因：按钮只切换路由，没有把工作方式切换为“问答生成”。
- 影响：用户无法通过页面提示的下一步走出空状态。
- 优先级：P1。

### B11：再次增强产生重复问题和嵌套前缀

- 复现：1 条问答增强为 2 条，再对该增强结果执行增强。
- 结果：第二次变成 4 条，其中“请向科研人员说明：原问题”重复两次，还出现“请向科研人员说明：请向科研人员说明：原问题”。
- 原因：保留原集合，再对所有已有问题直接拼接受众前缀，没有识别已增强条目或去重。
- 影响：重复样本持续增加，问题文本质量下降。
- 边界：这是当前本地演示增强逻辑的缺陷，不代表已经接入真正的模型改写。
- 优先级：P2。

### B12：知识片段可能切坏 Unicode 字符

- 复现：默认 180 字符切片，文本为 179 个汉字后接一个 emoji，再接其它文字。
- 结果：emoji 的高代理项 `d83d` 留在前一片，低代理项 `de00` 到下一片。1 字符切片运行中也验证到两个残缺片段。
- 原因：按 JavaScript UTF-16 单元直接 `slice`，没有按完整字符边界切片。
- 影响：导出和展示可能出现替代字符或损坏文本，涉及 emoji 及部分扩展字符。
- 优先级：P2。

## 3. 与模拟能力分开看

模型问答、图片描述和图片问答目前仍返回固定示例，真实模型及真实图像推理没有接入。这是已有实现边界，不把它重复计入本轮新 bug 数量。B08 指的是即使保留模拟输出，图片关联也应完整。

复杂标注、无目标负样本、外部图片 URL、标注配置及资源包导出仍属于未完成能力。本文主要列已经在现有交互和数据逻辑中复现的缺陷，没有以“应当支持所有 Label Studio 功能”作为本轮判断标准。

## 4. 建议修复顺序

2. 再修 B02/B03 输入切换、B09 模型辅助输入和 B10 空状态导航，打通连续操作。
3. 完善 B01 任务结果恢复、B08 图文输出结构，再处理小框、增强去重和字符边界。
